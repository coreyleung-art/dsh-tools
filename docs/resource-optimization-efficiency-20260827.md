# 资源优化效率评估报告（2026-08-27）

> 评估人：中枢协调者 fa1f9150 · 数据：实测（ps/pgrep/time）+ 估算
> 范围：Rust 化 + 最小上下文 + 事件驱动（本次全部优化措施）

## 一、内存优化（Node/Python → Rust）

| 服务 | 原内存 | Rust 版 | 节省 |
|---|---|---|---|
| bus-bridge | 36.9MB | ~10MB | 26.9MB |
| tailnet-proxy | 55.6MB | ~15MB | 40.6MB |
| learning-sub | 59.3MB | 6MB（bb-sub） | 53.3MB |
| **合计** | **151.8MB** | **31MB** | **120.8MB（80%）** |

+ dsh-tools 单二进制 428KB（替代 3 Python 脚本 + 运行时）
+ bb-sub ×7 = 41.8MB（新订阅器，原无此能力）

## 二、token 优化（最小上下文 v2.3）

| 指标 | 全文模式 | 短提示+本地摘要 | 节省 |
|---|---|---|---|
| token/条 | 1200 | 45 | **96.2%** |
| 50 条/日 | 60000 | 2250 | 57750 |
| 年化 | 2190 万 | 82 万 | **2108 万** |

**成本换算**（DeepSeek flash 约 ¥2/百万 input token）：
- 年省 2108 万 token × ¥2/百万 ≈ **¥42/年**
- 若部分走 pro（¥8/百万）：年省可达 ¥168/年
- 实际收益更大：上下文干净 → 少重试 → 少完整对话

## 三、CPU/轮询优化

- 全部常驻 Rust 服务 CPU 0.0%（SSE 阻塞，事件驱动零轮询）
- blackboard-subscribe 5min 轮询 → 事件驱动（bb-sub）省轮询开销
- 冗余服务停用 3 个崩溃循环（cld.server/blackboard-events/cmbc.monitor）——消除无限重启的 CPU/日志消耗

## 四、进程/部署优化

- Node 常驻 6 → 3（external-mcp/wecom 因官方 SDK 保留）
- 单二进制零依赖分发（i9 Windows 无需 Python/Node 环境）
- 三平台产物：mac 539KB / win 630KB / linux 711KB

## 六、方法论沉淀
